CI/CD pipeline with GitOps deployment to Amazon EKS

March to June 2026

Jenkins, SonarQube, Maven, Docker, Trivy, ArgoCD, Kubernetes, Amazon EKS, eksctl, Prometheus, Grafana

Every push runs through the stages in the scene, from checkout to a live deployment on EKS, in about 49 seconds end to end. Keep scrolling to follow one commit.

Checkout GitHub webhook, Jenkins on EC2

A push to GitHub fires a webhook. Jenkins, running on EC2, starts the declarative pipeline and checks out the commit.

Build Maven

Maven compiles and packages the Java application.

Analyze SonarQube

SonarQube analyses the code, and its Quality Gate stops the run when the code doesn’t meet the bar.

Scan Docker, Trivy

The app is packaged as a Docker image and Trivy scans it. A HIGH or CRITICAL vulnerability stops the release before it ships.

Push DockerHub

The image is loaded onto DockerHub, tagged with its build number, so any earlier version can be redeployed. Watch the ship in the harbour take it on board.

Deploy ArgoCD, GitOps

Jenkins updates the image tag in GitHub, and ArgoCD syncs that change to Amazon EKS. Git stays the record of what is running.

Release without downtime

Kubernetes rolls out the new version with maxSurge 1 and maxUnavailable 0 across 2 replicas. A new pod comes up before an old one is removed, and liveness and readiness probes keep traffic on healthy pods.

Scroll slowly to watch the orange pods replace the blue ones.

Watch it, then shut it down

Prometheus and Grafana track pod health and resource use across the cluster. The cluster is created and deleted with eksctl for each working session, so nothing sits idle on the AWS bill.

DockerHub, GitHub and SonarQube tokens live in Jenkins Credentials Manager, never in the source code.

Multi-AZ web hosting on AWS with Auto Scaling

February to March 2026

Terraform, VPC, EC2, Auto Scaling, Application Load Balancer, IAM, S3, Docker, Nginx, Bash, AWS CLI

A custom VPC (10.0.0.0/16) with public and private subnets, route tables and an internet gateway keeps internet-facing and internal resources apart. Terraform provisions the VPC, subnets, route tables and EC2 instances, with terraform plan reviewed before every apply and terraform destroy run after testing.

Traffic across two Availability Zones

Nginx runs in Docker on an EC2 Auto Scaling Group, built from a launch template and a custom AMI, behind an Application Load Balancer that spans two zones. When an instance fails, the group replaces it automatically.

Bash user data sets up each instance at boot, and Bash scripts using the AWS CLI start and connect to instances instead of repeating steps in the console. An IAM role gives the instances read-only S3 access, with no access keys stored on them.
